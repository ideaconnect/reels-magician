# Changelog

Changes to ReelsMagician, newest first.

## Unreleased

### Changed

- **Step strip:** the row of steps at the top of the window now looks like the app's menu. It is a bar of its own, with the page it opens framed under it, and each step is a rounded chip: the open one in the accent colour, the rest muted. The chips show your progress too. A step's number turns into a check once its output exists, the step to do next has its number ringed, and the steps after it are dimmed, though you can still open them. **Cleanup** stays on the right, outlined and unnumbered, so it does not read as a seventh step. Screen readers hear each chip as, for example, "Step 3 of 6, Subtitles, done".
- **Icons:** the app now draws icons from Font Awesome Free. On the Setup tab each component starts with a green check when it is installed or found on the system, a red X when it still has to be downloaded, and a grey dash when it is optional and not installed, so the states no longer differ by colour alone. A component's warning, such as a Fallback build, gets an amber warning sign. The buttons show an icon before their text, and the step strip's checks and the support bar's cup and heart are Font Awesome's too. Font Awesome's licence is listed with the others and ships with the app.
- **Light and dark themes:** the violet dark theme is replaced by two neutral ones: a true-black dark theme for OLED screens, and an off-white light theme that doesn't glare on IPS screens. By default the app follows the system's light or dark setting, live; a switch at the top right of the window picks **follow the system**, **light** or **dark**, which applies at once and is remembered. The buttons and the selected step take the system's accent colour where it has one, and a blue from the new icon's film strip where it doesn't. On Linux the app follows the desktop's portal, and where that doesn't say dark or there is no portal, as is common on sway, GTK's own setting; with no answer from either it is light, so a Linux desktop that states no preference now gets the light theme where it used to get the dark one. The palette's text colours reach 4.5:1 contrast on their backgrounds in both themes.
- **App icon:** a new icon, a film reel rising out of a magician's hat, replaces the violet phone everywhere: the Windows `.exe`, title bar and taskbar, the AppImage and its desktop entry. It also sits beside the app's name at the top of the window. On Windows the title bar and the taskbar now get a frame drawn for their size and display scaling, instead of a 256 px image scaled down, and the message boxes and file picker show the icon too. The smallest size, 16 px, shows the reel alone, which stays recognisable where the whole drawing would blur. On Linux, GNOME and KDE show the icon in the dock once the AppImage is integrated with the desktop, for example by Gear Lever or AppImageLauncher; the README explains why.
- **Scrolling:** a page or list taller than the window no longer stops with a hard edge that slices a card or a button in two. Its top and bottom edges fade out while there is more to scroll to on that side, so it shows that the page goes on, and each fade goes once you reach that end; a page that fits shows none. The fade follows the theme: to black in the dark theme, and to the background with a slight shadow in the light one. The activity log, which scrolls inside the Render page, fades inside its own frame. A control reached with Tab, or a row reached with the arrow keys, is scrolled clear of the fade rather than to the very edge, and the pages leave a little room under their last card.
- **About tab:** a new **About** tab beside **Cleanup** says which version you are running (or that it is a development build), the system it runs on and where the data folder is, with **Copy path**. It says who makes the app, IDCT, with a link to idct.tech, and links to the GitHub repository, its issues (**Report a problem**) and its releases. It lists every licence involved: the app's own BSD 3-Clause License and each component's, grouped by how it reaches you, as THIRD-PARTY-NOTICES.md groups them, with Font Awesome's credit. **View licence** shows the text the build carries in the app itself, which also works inside the AppImage, where the files used to be out of reach. The tools and models the app downloads are marked installed or not, so you can see which terms apply on your machine: GPL-3.0 for its ffmpeg, NVIDIA's CUDA EULA where a CUDA build was installed, and GPLv3+ for yt-dlp. A build not made from a release tag now calls itself a development build instead of 0.1.0. The IDCT and ReelsMagician names and logos are not covered by the BSD 3-Clause License; the README and THIRD-PARTY-NOTICES.md now say so.
- **Notes and warnings:** the explanations on each tab used to be small grey text in the same style as the labels and data around them, and were easy to skip. Each one now sits in a box of its own with a blue information icon, at the normal text colour, so it reads at full contrast. Warnings look the same everywhere: an amber box with a warning sign, both for a source below 4K on the **Source** tab, which used to be a filled box with no icon, and for a component's warning on the **Setup** tab, such as a Fallback build, which used to be amber text under its row. Screen readers announce each one as "Information: …" or "Warning: …". Paths, sizes, states and summaries keep the small grey style. One short note beside a field, the one beside **Grow amount** on the **Captions** tab, shows its icon without the box, so the card doesn't get heavy. On **Source**, **Render** and **Cleanup** the note next to the buttons now sits beside them, as on **Subtitles** and **Reel**, so those pages still fit the window at its default size.
- **Memory warnings:** the Setup tab now says what the chosen model needs at the context it runs with, instead of notes that understated it: Qwen3 8B (Q4_K_M) needs about 9.7 GB of graphics memory at 32k, not "~6 GB". It compares that with what this computer has: what llama.cpp itself reports once it is installed, which counts the system memory integrated graphics share, and before that what the system reports for the card, or the computer's own memory where a model runs on the processor. A model that probably won't fit gets an amber sign in its drop-down and a warning under it. You can still run it: the first analysis or transcription with it asks first, with **Cancel** as the default. Unless `llamaGpuLayers` is set in settings.json, llama.cpp now fits the model to the graphics card itself, so a model too big for it runs with some of its layers on the processor, more slowly, instead of failing. On Linux, on an integrated Radeon, it leaves 3 GB of the shared memory free instead of llama.cpp's usual 1 GB: what the model keeps on the processor's side comes out of that same memory, so with the smaller margin a model close to the limit could be planned to fit and still fail as it started. A model that runs out of memory says so, "The model didn't fit in the graphics memory. Choose a smaller model.", instead of showing llama.cpp's log, and if the app or the computer goes down while a model runs, the next start says which model it was and suggests a smaller one.
- **Polish interface:** the whole interface is now in English and Polish. A list beside the theme switch picks **System language**, which is Polish on a Polish system and English on any other, **English** or **Polski**; it switches at once, without a restart, and is remembered. Counts take the form Polish gives them ("1 napis", "3 napisy", "5 napisów"), and sizes, times and numbers on screen are written the Polish way ("22,5 MB"), following your regional settings where they are Polish too. What a machine reads stays as it was in either language: the log, which goes into bug reports, settings.json, and every number given to ffmpeg or written into a caption file. The logic checks now run a second time under Polish regional settings to hold that. The step strip now gives each step its full width again after the language changes, so a longer name is no longer cut.
- **Windows installer:** each release now comes with `ReelsMagician-win-x64-Setup.exe` beside the zip. It installs the app for your account, with no admin rights, into `%LOCALAPPDATA%\IDCT.ReelsMagician`, puts shortcuts in the Start menu and on the desktop, and lists the app under **Installed apps** in Settings with its publisher, version and icon, so you can uninstall it from there. Uninstalling removes the app and its shortcuts and leaves the data folder, `%LOCALAPPDATA%\ReelsMagician`, with its tools, models and settings, as it is: free the space from the **Cleanup** tab first, or delete the folder afterwards. The installer and the zip share that folder, so moving from the zip to the installer downloads nothing again. The zip stays for anyone who prefers to unpack and run. Neither is signed yet, so SmartScreen still asks once. The installer is built with Velopack, which the About tab lists with its licence, and the release also carries the package and `releases.win.json` that automatic updates will need.
- **Updates:** once the window is up, at most once a day, the app asks GitHub whether there is a newer version, sending nothing but its own version as `User-Agent: ReelsMagician/<version>`. Without a connection it says nothing, so local videos still work offline, and a development build never asks. A newer version shows in a box in the status area and on the **About** tab, with its release notes as text, and **Update now**, **Later** and **Skip this version**. Nothing is installed until you choose **Update now**, which waits for a running step to finish and asks first while a video is open, as a restart closes it. The installed app on Windows updates through Velopack and starts again in the new version; it can do that from the first release with an installer onwards, as Velopack sees only releases that carry `releases.win.json`. The Linux AppImage downloads the new image beside itself and renames it over the old one, and **Restart now** starts it; in a folder it can't write to, such as `/opt`, and for the Windows zip, the app links to the release page instead. Every download is held to the sha256 digest and size GitHub gives the release asset, and comes over HTTPS from GitHub only; an asset without a digest isn't installed. The **About** tab has **Check for updates** (on), **Include pre-releases** (on, as every release so far is one) and **Check now**.

### Fixed

- **Setup lists:** in **Required tools**, a model's name was cut off just where it says which one is recommended (`Whisper large-v3-turbo (quantised) — recom…`), and further in Polish, with no way to read the rest. The name column now widens to the longest name, up to a limit that leaves the details room, and **Video links** lines up with it. A name or detail still too long for its column, as at the window's smallest size, shows whole in its tooltip.
- **Context on a new install:** a new install ran the default model, Qwen3 8B (Q4_K_M), at a 16k context, although choosing it on the Setup tab gives it 32k, so the same model got half the context until it was chosen again. A new install now starts at the context the model list gives the default model, 32k, which needs about 9.7 GB of graphics memory instead of 7.4 GB; where this computer has less, the Setup tab warns, as for any model too big for it. An install that already has a settings.json keeps its context until you choose a model on the Setup tab.
- **Amber subtitles:** on the **Subtitles** step, subtitles that came with the video showed in amber, as if Whisper had been unsure of them, although Whisper never ran on them: every line of a subtitle file beside a local video or brought in with **Import…**, and of a link's subtitles that carry no word timings. Their words get made-up timings, and those came with a made-up confidence. Now only what Whisper was unsure about is amber: subtitles that came with the video never are, and editing a line no longer turns it amber. A line keeps Whisper's confidence in the words you replaced, so one it was unsure of stays amber, with **edited** beside it. A cue Whisper gave no time of its own, which the app folds into the one before, keeps Whisper's confidence too, where it used to turn that line amber.

## 0.2.0 (2026-11-08)

The first release that runs on Linux as well as Windows, and the first with ready-to-run packages: a zip for Windows and an AppImage for Linux. Still an early preview.

### Windows and Linux

- **Processing core:** the core now builds for Linux as well as Windows, and passes the same checks on both.
- **Linux graphics:** on Linux the app finds the graphics card, and Vulkan support, from the system itself.
- **Linux archives:** tool archives in the formats Linux builds use (`.tar.gz`, `.tar.xz`) unpack with their permissions and links intact.
- **OpenCV:** face and people detection now use OpenCvSharp 5, on OpenCV 5.0. On Linux the app ships OpenCV's headless build, so it needs nothing from the desktop: no GTK 3 to install.
- **Releases:** Windows gets a zip with everything included; Linux gets a single AppImage that needs only FUSE 3, which Ubuntu installs by default. The app has an icon of its own for the first time. Both carry the licences of everything they include, in a `licenses` folder next to the app.
- **New interface toolkit:** the interface is rebuilt on Avalonia, so the same app runs on Windows and on Linux, where it runs natively on Wayland. The tabs, wording and colours stay as they were.
- **The app's own dialogs:** the app now draws its own file pickers and confirmation dialogs instead of using the system's, so they look and behave the same on both systems. Questions still default to the answer that changes nothing.
- **Copy path instead of Open folder:** the reel and the data folder have a **Copy path** button, which works the same on every system. **Open folder** and **Open data folder** are gone: they handed the folder to the system's file manager, which a Linux desktop may not have, and there the buttons did nothing.
- **Linux downloads:** on Linux the app downloads Linux builds of every tool. llama.cpp runs on the graphics card through Vulkan; whisper.cpp runs on the processor, since that is the only Linux build its publisher offers.

### Changed

- **Supporting the app:** a bar at the bottom of the window links to Buy Me a Coffee and GitHub Sponsors. ReelsMagician is free and open-source software, and that is how to help keep it going.
- **Fallback builds are reported:** when the best build of whisper.cpp or llama.cpp that this machine supports cannot be found and a lesser one is installed instead (a CPU build on a machine with a capable graphics card, say), the app says so during the install and on the Setup tab, instead of quietly running slower.

- **Video links:** yt-dlp and Deno are no longer part of the default install. **Install everything missing** never fetches them. The app downloads them only after you agree, either the first time you load a compatible video link or from the optional card on the Setup tab. A yt-dlp already on your PATH is used without asking.
- **Face detection:** faces are now found by YuNet, the face detector in OpenCV's model zoo. It also finds a head turned to the side and a small face, such as a webcam in the corner of a screen recording, and takes about a quarter of the time per frame. It is a 0.2 MB download instead of 11 MB: press **Install everything missing** once to get it, and the old detector's files are deleted.
- **Reel names:** a reel's file name is now made of ASCII letters, digits and underscores only: `Laptop czy tablet? Wszystko w jednym` becomes `Laptop_czy_tablet_Wszystko_w_jednym`. It comes out the same on Windows and Linux, and copies to any USB stick or shared folder. The suggested name for exported subtitles is made the same way.
- **Links without ffmpeg:** loading a link before ffmpeg is installed now stops and points you to Setup, instead of failing after the download.
- **Cleanup tab:** **Free up space** moved from the Setup tab to a tab of its own, **Cleanup**, on the right of the tab strip, apart from the six steps. It measures the data folder afresh each time it opens.
- **Buttons on the right:** every step's buttons now sit on the right, with its main action rightmost, and so do the confirmation dialogs and the file picker. A question still has the answer that changes nothing selected, so Enter never agrees by accident.

### Fixed

- **Repeated speech:** words spoken again were sometimes dropped or cut short, as if they were a caption repeating the previous line. Only a real rolling repeat is trimmed now: one that starts as the previous cue ends and repeats it on a line of its own.
- **One-word captions:** in captions that come with a video, a line adding a single new word could appear up to a second late. It now appears when that word is spoken.
- **Free up space:** after deleting, the status bar says how much was freed, or which files are still in use, instead of only "Freeing up space complete.". A progress line arriving late from a finished step can no longer replace that, or the path of a rendered reel.
- **Failed installs:** when an install fails or is cancelled partway, the Setup tab now shows the tools it did install, instead of listing them as missing until you press **Refresh**.
- **Typed paths:** a source or output folder typed as `~/Videos/…` now starts in the home folder, instead of failing to load or creating a folder named `~`. A relative output folder no longer fails the render after it has started; it is taken from the home folder, and an empty one means the default folder.
- **Quoted links:** a link pasted in quotes skipped the ffmpeg check and the question before yt-dlp is downloaded. Quotes are now removed once, before anything looks at the input, and single quotes from a Linux terminal are removed too.
- **Where the reel went:** after a render, the status bar could say "Reel complete" instead of naming the file it wrote. It names the file again.
- **Stale previews:** a caption preview still rendering when another video loaded could put the old video's frame back on screen.
- **Free up space:** the "Downloaded tools" row named yt-dlp and Deno even when they had never been downloaded. It now names what is actually there.
- **whisper.cpp on NVIDIA:** whisper.cpp renamed its CUDA builds, and the app stopped recognising them, so NVIDIA cards quietly got a CPU build. Both the old and the new names are recognised again, and the newest CUDA build the card's driver can run is chosen.
- **Failed loads:** a failed or cancelled load no longer throws away the current transcript and plan. The new source replaces the project only once it has loaded. A successful load also clears the subtitles, reels and preview left over from the previous video.
- **Automatic captions:** word-timed automatic captions that come with a video no longer lose lines or show others twice.
- **Drop-down lists:** a closed drop-down list could show the wrong text for the selected item.
